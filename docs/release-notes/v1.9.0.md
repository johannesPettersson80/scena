# scena 1.9.0

Release candidate prepared: 2026-07-21

scena 1.9.0 is a correctness, portability, agent-workflow, proof-quality, and
interactive-performance release. It closes the implementation portion of the
v1.8.0 full-repository review remediation while keeping larger renderer
features such as cascaded/point/spot shadows, an HDR post chain, glTF export,
animation crossfades, and Draco decoding as separately governed follow-up
projects.

## Renderer correctness and defaults

- Parallel CPU rendering now consumes every row band even when an OIT pass is
  found, preventing Rayon short-circuiting from leaving bands undrawn.
- Cone and wedge winding, cone/cylinder UV seams, near/far CPU clipping,
  cross-platform-stable raster/clipping boundaries, and visible-bounds framing
  now follow the same contracts as the GPU path.
- High-level viewers conditionally provide neutral presentation for otherwise
  unlit PBR scenes and retain actionable frame diagnostics instead of returning
  an unexplained successful black image.
- Browser readback transfer is selected from the actual target format. SDR
  post-processing remains linear until its explicit output transfer.
- Device loss is terminal for the old device, surface acquisition distinguishes
  retryable and terminal outcomes, and browser MSAA requests report/degrade by
  capability rather than failing without context.
- The native present-only path avoids a redundant scene render, uses a real
  MSAA resolve target, shares device-owned shader modules, and no longer performs
  a blocking GPU wait during routine prepare.

## Assets, animation, and scene semantics

- Agent templates and the Studio environment preset use embedded,
  provenance-documented radiance bytes and work outside a repository checkout.
- Z-up imports convert linear, step, and cubic-spline rotation animation data
  into the target basis, including cubic derivative handling.
- Explicit hot reload transactionally replaces changed external texture bytes
  while preserving stable handles and the last complete scene on failure.
- Scene-cache reuse now includes semantic load options instead of allowing a
  lenient path-only entry to satisfy a stricter request.
- glTF imports compute missing normals, honor or reject texture UV-set semantics
  explicitly, reduce eight skin influences deterministically with diagnostics,
  apply node morph-weight overrides, and validate anchor/connector orientation
  data before resource commit.

## Agent and CLI workflows

- Recipe render, inspect, diagnose, doctor, and repair use the same complete,
  policy-aware resource plan as validation; multiple imports and authored
  environments, fonts, and textures are no longer silently dropped.
- `scena capabilities [--live] [--json]`, repeatable `--allow-root`, successful
  per-command help, `examples agent list`, canonical template aliases,
  `diff --exit-code`, and structured nearest-name candidates make planning and
  correction machine-readable.
- `scena-convert` emits a stable JSON envelope and captured diagnostics.
- The opt-in `agent` feature composes the inspection and SceneHost surfaces;
  default crate features remain empty.
- Recipe imports and authored nodes share the tagged `kind: "trs"` / `kind:
  "raw"` transform grammar. The v1.8.0 untagged import shape remains accepted
  with a migration warning.

## Proof and release integrity

- Required WebGPU proof now compares real hardware pixels with a source-bound
  CPU oracle and emits parity metrics, heatmaps, worst-region evidence, and
  rejected-mutation results.
- GPU lifecycle evidence requires a physical adapter and a completed
  prepare/render/release/poll cycle with no pending destruction; optional
  adapter-less smoke tests emit typed skips rather than vacuous passes. The
  required artifact binds its producer source and dependency lockfile with
  SHA-256 checksums before staging and belongs to the physical macOS Metal
  lane, not the hosted Linux software-Vulkan lane.
- Hosted performance evidence gates steady-state p95 allocation counts and
  maximum allocated bytes while reporting observed maximum allocation counts;
  periodic Rayon scheduler maintenance no longer masquerades as product heap
  growth, and the stored allocation budget is unchanged.
- Material visual checks use effect-specific regions and meaningful floors, and
  the M2 oracle uses local structure, edge, foreground, heatmap, and
  mean-preserving mutation checks instead of quadrant means alone.
- Release readiness requires an explicit artifact root and every declared
  artifact, including Linux Vulkan output. The final Windows proof is a
  checksum-bound, exact-commit, one-command bundle covering WebGPU, WebGL2,
  native-surface, lifecycle, and controlled shader-cache evidence.
- The automated local release sweep now closes two high-severity RustSec
  advisories by updating the compatible Wayland scanner patch to use
  `quick-xml 0.41.0`. Release-lane schema tests use isolated fixtures, so prior
  generated command evidence cannot change unit-test results.

## Performance and ergonomics

- Animation mixers share immutable clip data, skinning reuses source-node and
  per-joint transforms, CPU resolve defers eligible output encoding, doctor
  scans memoize source reads, and labels share glyph bytes.
- `Transform::scale_by` is now multiplicative, matching its composing name.
  Existing setter-style calls should move to `with_scale` or
  `with_uniform_scale`.
- `GeometryDesc::polyline` is deprecated for untrusted/runtime input; use the
  fallible `GeometryDesc::try_polyline` contract.
- Pointer capture prevents custom-element orbit interaction from sticking when
  release occurs outside the element.

## Evidence and migration

The item-by-item implementation evidence, focused tests, scoped gates, final
integration checkpoint, deferred-feature boundary, and hardware acceptance
ledger live in the
