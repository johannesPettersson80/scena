# scena 1.8.0

Release date: 2026-07-19

## Post-release errata

- The v1.8.0 documentation used "persistent" recipe-ID wording without
  defining a persisted-document contract and left multiple historical plans
  looking active. Current unreleased documentation defines `SceneRecipeV1` as
  a versioned interchange/build input, records its canonicalization and unknown
  field limits, keeps host persistence/migrations out of renderer scope, and
  identifies one active remediation backlog. This correction was not part of
  v1.8.0.
- The renderer and doctor performance corrections described in the current
  unreleased changelog were not part of v1.8.0. Their deterministic work
  counters and focused parity tests are current source evidence; no
  physical-GPU shader-prepare latency improvement is claimed until the pending
  hardware acceptance run is recorded in the remediation checklist.
- The published v1.8.0 doctor test-pin helper accepted an ignored `#[test]`,
  and the early-return scan allowed any file containing the words
  `fail_closed` or `release_evidence` to bypass control-flow policy. Its demo
  and proof cache-buster metadata also remained on v1.7.1. Current unreleased
  builds require active non-ignored test items, exact owner/rationale
  allowlisting, mutation-test the five silent-failure families, and derive
  tracked/generated public versions from `Cargo.toml`. This correction was not
  part of v1.8.0.
- The published capability and frame-stat contracts reported a directional
  shadow PCF kernel of 3 while the fragment shader issued one linearly filtered
  depth comparison, an implicit 2×2 footprint. Current unreleased builds issue
  and average nine nearest-filtered comparisons over an explicit 3×3 texel
  grid in both GPU shader variants. This correction was not part of v1.8.0.
- The published C09 GPU resource-lifecycle tests silently returned when no
  adapter was available, allowing a green run with no lifecycle assertions.
  Current unreleased builds label those checks optional and emit typed skip
  artifacts, while a separate physical-hardware test and release consumer
  require adapter provenance, a complete prepare-render-release-poll cycle,
  and zero pending destructions. This correction was not part of v1.8.0.
- The published v1.8.0 required browser WebGPU lane treated hardware identity,
  submissions, draw calls, and nonblack pixels as parity, so a materially wrong
  image could pass. Current unreleased builds compare the renderer readback to
  a source-bound CPU oracle, reject six image mutations, emit heatmap and
  worst-region evidence, and make the release consumer require those pixel
  results. This correction was not part of v1.8.0.
- The published app-builder instructions redundantly requested both
  `scene-host` and `inspection` even though the former already enables the
  latter, while default-build command errors named a feature but no executable
  install remedy. Current unreleased builds add the opt-in `agent` composition,
  preserve empty defaults, and report one-step Cargo install/run guidance. This
  correction was not part of v1.8.0.
- The published recipe contract used tagged transforms for authored nodes but
  an untagged raw `Transform` for imports and placement/patch output. Current
  unreleased builds use the tagged grammar everywhere, retain the old import
  and placement-result shapes as narrow v1 readers, emit a migration warning
  for old recipe imports, and always serialize canonical discriminators. This
  correction was not part of v1.8.0.
- The published lookup paths often returned only a failed name, schema and
  template suggestions were prose-only, animation/host conversion discarded
  valid alternatives, and `NoActiveCamera` Display omitted its actionable
  remedy. Current unreleased builds expose one deterministic, capped
  `candidates` list across typed and JSON errors and preserve the camera remedy
  through SceneHost serialization. This correction was not part of v1.8.0.
- The published repair command accepted a raw `<asset-or-recipe>` positional
  without loading a raw asset before planning from `--from`; recipe doctor also
  had a direct-asset compatibility path in the reviewed baseline. Current
  unreleased builds validate raw repair targets through asset doctor, retain
  full policy-aware recipe validation/build, reject duplicate targets, and
  lock recipe doctor to `scena.recipe_build_result.v1`. This correction was not
  part of v1.8.0.
- The published `scena-convert` mixed a JSON dry-run with prose errors and
  inherited external-tool output, and its JSON had no stable schema envelope.
  Current unreleased builds add `scena.asset_conversion.v1`, explicit
  `--json`/`--human` modes, captured machine diagnostics, and stable domain
  exit semantics. This correction was not part of v1.8.0.
- The published v1.8.0 CLI returned argument errors for per-command help,
  exposed template names only through errors, used two visually similar
  product-configurator spellings for different templates, and always exited 0
  for a valid unequal diff without an explicit CI mode. Current unreleased
  builds add successful command help, a stable template catalog with canonical
  names/aliases, and `diff --exit-code`. This correction was not part of
  v1.8.0.
- The published v1.8.0 capability surface had no pre-render discovery command,
  factory rows did not identify themselves as static, and CLI version metadata
  listed only `inspection` and `scene-host`. Current unreleased builds add
  `scena capabilities [--live] [--json]` with explicit static/live/unavailable
  provenance and complete compiled-feature metadata. This correction was not
  part of v1.8.0.
- `validate-recipe` now resolves every authored resource family through the
  same policy plan as recipe build. The prior asset-aware pass checked imports
  but could defer missing environments, fonts, and material textures until
  build. Use `--syntax-only` for an explicitly non-equivalent no-I/O check.
- The published v1.8.0 CLI could tell operators to update
  `RecipeBuildPolicy` after rejecting an intentional external model library,
  but exposed no way to do so. Current unreleased builds add repeatable,
  canonical `--allow-root <directory>` options across policy discovery,
  validation, build, render, inspect, diagnose, doctor, and repair. There is no
  sandbox-disable switch, and traversal/symlink escapes remain denied. This
  correction was not part of v1.8.0.
- Generated `recipe inspect-cad` views now use the oriented studio-light rig
  and a +0.25 EV presentation adjustment; the prior co-directional preset
  lights could black-crush a principal face and make the command fail its own
  quality verification.

- The original v1.8.0 `xtask release-readiness` command could report success
  when `SCENA_RELEASE_ARTIFACT_ROOT` was unset and no evidence was validated.
  Current unreleased builds require an explicit `--artifact-root` or non-empty
  environment value, report the resolved root and validated count, and require
  Linux Vulkan `rendered-output.json` to exist. This correction was not part of
  the published v1.8.0 binary.
- The published v1.8.0 high-level glTF viewer could return a successful black
  PBR frame when the asset authored neither lighting nor an environment, while
  the actionable diagnosis required a separate call. Current unreleased builds
  apply a conditional neutral presentation and retain its structured warning
  on the high-level result. This correction was not part of v1.8.0.
- The published v1.8.0 browser WebGPU no-post readback path selected sRGB
  encoding from the post-enabled flag. A plain unorm readback target therefore
  exposed linear bytes that consumers interpreted as sRGB, producing a dark
  capture. Current unreleased builds select transfer from the actual target,
  keep SDR post math linear through sRGB intermediates, and report the selected
  target format. This correction was not part of v1.8.0.
- The published v1.8.0 Z-up import path converted static node rotations but
  left rotation animation channels in the source basis, so playback could snap
  away from the correct rest pose. Current unreleased builds basis-conjugate
  linear, step, and cubic-spline quaternion data, preserving cubic derivative
  magnitudes. This correction was not part of v1.8.0.
- The published v1.8.0 reload path treated changed bytes for an already-decoded
  external texture as an immutable cache-identity collision. Current
  unreleased builds make explicit reload the transactional source-replacement
  boundary, preserve the same-path texture handle, and keep the last complete
  scene on dependency failure. This correction was not part of v1.8.0.
- The published v1.8.0 scene cache was keyed only by source path, so a lenient
  load could satisfy a later strict request without rechecking missing-resource
  or byte-budget policy. Current unreleased builds key and qualify reuse with
  semantic load options and retained evidence, and report both request and
  cache-entry policy. This correction was not part of v1.8.0.
- The published v1.8.0 device-loss path cleared prepared resources and reported
  recovery while retaining the terminal wgpu Device/Queue. Current unreleased
  builds keep device loss latched, return typed renderer-rebuild guidance before
  polling or allocation, and require a fresh renderer/device before prepare and
  submission. This correction was not part of v1.8.0.
- The published v1.8.0 native surface path silently ignored timeout, occlusion,
  outdated, lost, and validation acquisition results while continuing to return
  success. Current unreleased builds retry `Outdated` once, latch `Lost` for
  surface recreation, classify counted skips separately, and fail closed on
  validation, OOM, repeated churn, or configuration changes. This correction
  was not part of v1.8.0.
- The published v1.8.0 CPU rasterizer discarded a whole triangle whenever any
  vertex lay before the near plane or beyond the far plane. Current unreleased
  builds clip once before binning, retain all prepared vertex attributes, and
  share the clipped projection across opaque, transparency, transmission, and
  semantic AOV paths. This correction was not part of v1.8.0.
- The published v1.8.0 glTF importer fabricated `(0,0,1)` when `NORMAL` was
  omitted, ignored ordinary texture-info UV-set requests, dropped
  `JOINTS_1/WEIGHTS_1`, and ignored node-level morph-weight overrides. Current
  unreleased builds compute reported flat normals, fail closed on unsupported
  texture UV sets, deterministically reduce eight source skin influences to
  four with a structured warning, and apply node overrides before animation.
  These corrections were not part of v1.8.0.
- The published v1.8.0 anchor/connector extras parser could silently replace an
  invalid forward/up basis or malformed matrix with identity, and connector TRS
  fields were not validated consistently with anchors. Current unreleased
  builds validate both marker types at load time and reject the exact authored
  path before committing any asset resources. This correction was not part of
  v1.8.0.
- The published v1.8.0 generated KHR material screenshots could satisfy some
  feature checks with only a one- or two-LSB change and did not exercise a
  wrong-direction control. Current unreleased builds use feature-specific
  regions and visible-effect floors, render anisotropy under two light
  directions, and require disabled and inverted-effect mutations to fail while
  tolerating harmless one-LSB output noise. This proof correction was not part
  of v1.8.0.
- The published v1.8.0 M2 reference gate compared only quadrant aggregates, so
  a mutation could preserve quadrant means while moving or collapsing structure
  inside each quadrant. Current unreleased builds use committed source frames,
  local SSIM/edge/foreground metrics, diff heatmaps, worst-region boxes, and
  two mean-preserving rejected mutations. This proof correction was not part
  of v1.8.0.
- The published v1.8.0 `Transform::scale_by` replaced existing scale even
  though the neighboring rotation helpers compose. Current unreleased builds
  make `scale_by` multiplicative and provide `with_scale` and
  `with_uniform_scale` for explicit replacement. Replace old setter-style
  calls with `with_uniform_scale`. This correction was not part of v1.8.0.
- The published v1.8.0 generated cylinder and cone side UVs wrapped the final
  side triangles from the last local interval back to `u=0`, causing those
  triangles to sample backward across almost the entire texture. Current
  unreleased builds duplicate the closing position and normal at `u=1` and
  keep cone tips face-local. This correction was not part of v1.8.0.
- The published v1.8.0 custom element could retain orbit state after a mouse
  release outside its bounds; browser MSAA requests also hard-failed without a
  portable profile fallback, and `SCENA_USE_GPU` could silently change CLI
  execution despite being documented as metadata-only. Current unreleased
  builds capture/clean pointer state, report browser sample-count matrices with
  automatic FXAA fallback, reserve exact MSAA for fail-closed requests, and use
  only explicit `--gpu` CLI selection with result provenance. These corrections
  were not part of v1.8.0.
- The published v1.8.0 aggregate framing helpers centered all known bounds from
  a dead-front view using the camera's previous aspect, and `center_on` moved a
  node origin rather than visible content. Current unreleased builds route
  aggregate/import fitting through `FramingOptions`, pass actual viewer target
  dimensions, exclude hidden/helper geometry by default, expose helper
  inclusion, and split origin movement from visible-bounds centering. This
  correction was not part of v1.8.0.
- The published v1.8.0 API still presented the panicking `GeometryDesc::polyline` wrapper
  beside its fallible alternative. Current
  unreleased builds deprecate that wrapper, document
  `GeometryDesc::try_polyline` as the runtime/untrusted-input path, and retain
  recipe validation/build rejection for fewer than two points. This correction
  was not part of v1.8.0.

## Highlights

- Added renderer-free, machine-readable authoring workflows for recipe field
  discovery, policy discovery, canonical builds, persistent placement edits,
  deterministic multi-view capture, semantic AOVs, and attributed recipe
  diffs.
- Added recipe-owned anchors, connectors, mates, bounds, non-renderable groups,
  inherited presentation state, and stable node and instance attribution across
  build, capture, AOV, and diff outputs.
- Added asynchronous browser capture and typed render introspection while
  retaining the existing synchronous CPU and WebGL2 interfaces.
- Accelerated asset-aware picking and CPU shadow visibility with deterministic
  geometry and prepare-owned spatial indexes, and added bounded parallel native
  environment baking and CPU raster preparation.

## Renderer correctness and quality

- Fixed CPU normal-map evaluation, glTF quantized and sparse deformation
  import, cubic-spline morph weights, non-meter import placement, finite
  transform atomicity, handle namespace isolation, presentation-timeline
  bounds, generated annotation ownership, and deformed picking.
- Moved retained GPU target creation and post-processing depth bindings into
  prepare-owned lifecycle state, added present-only and asynchronous readback
  modes, and removed redundant warm-frame cloning and CPU occlusion work.
- Made WebGPU and WebGL2 output toggles render real nonblank content on hardware
  and fixed the ANGLE D3D11 dynamic-pixel-executable failure by bounding the
  generated shader loop shape used by the WebGL2 path.
- Replaced fragile pixel and exact-hash checks with tolerant full-frame visual
  oracles and effect-footprint mutations for lighting, shadows, IBL, AA, bloom,
  SSAO, transparency, clipping, and material appearance.
- Corrected the data-visualization agent template so its appearance proof
  samples a tagged authored blue mark rather than a textured fixture whose
  decoded texture invalidated the declared blue expectation.

## Performance and diagnostics

- Added measured warm-allocation, texture-bake, environment-bake, animation,
  output-toggle, spatial-acceleration, and CPU-occlusion evidence with explicit
  counters instead of placeholder claims.
- Added reusable renderer-owned scratch resources, bounded texture baking,
  cached tangents and transforms, indexed animation and instance lookups, and
  content-addressed embedded texture identities.
- Added structured failures for strict GPU construction, malformed recipe
  spatial state, invalid compressed-texture roles, unsupported WASM filesystem
  output, and missing release provenance.

## Release assurance

- Expanded `xtask doctor` to enforce feature ownership, module boundaries,
  onboarding and schema contracts, renderer lifecycle rules, visual proof,
  performance evidence, browser backend parity, and source-derived release
  provenance.
- Added exact-commit artifact staging, known-bad substitution tests, and
  fail-closed GitHub release workflows. Technical evidence remains mandatory;
  an unsatisfiable seven-person review bundle is no longer a publication
  prerequisite, and doctor rejects its reintroduction. Publication also no
  longer waits forever on an unregistered self-hosted GPU runner: hosted
  WebGPU conformance remains mandatory and is explicitly not labeled as
  physical-hardware evidence.
- Isolated platform performance baselines from parallel functional tests and
  run their exact benchmark command single-threaded on every native release
  lane. GitHub-hosted wall-clock results are explicitly report-only because
  those virtual machines are not controlled performance hardware; sample
  validity and allocation budgets still fail the release lane, while the 5%
  timing threshold remains strict on controlled hardware.
- Verified the combined WebGPU and WebGL2 PF01 output-toggle path on an Intel Arc
  Pro Windows laptop with hardware attestation and renderer-owned readback.
- Added an investigation circuit breaker, exact-run CI evidence collector,
  serialized heavyweight CLI subprocess proof, and a one-command Windows proof
  bundle so repeated identical failures stop for root-cause evidence before
  another patch, push, or user-assisted run.

## Compatibility

This is a backward-compatible minor release. Existing scene, renderer, asset,
and browser entry points remain available; new strict or typed alternatives are
explicitly named so callers can opt into fail-closed behavior.
