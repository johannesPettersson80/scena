## Camera-behavior easy path

This draft adds a subject-driven camera-behavior workflow to the public CLI and
recipe surface:

```bash
scena photo render model.glb --out hero.png --report hero.report.json
```

The recipe-native form is:

```json
{
  "schema": "scena.scene_recipe.v1",
  "imports": [{ "id": "subject", "uri": "model.glb" }],
  "photo": {
    "intent": "camera_behavior",
    "subject": { "kind": "import", "id": "subject" }
  }
}
```

The camera path derives composition, subject metering, bounded exposure
correction, and subject focus from the resolved subject. It is designed for the
first product/model hero still to work without hand-authored camera distance,
fixed exposure EV, guessed focus distance, floor, grid, or background constants.

## New contracts

New versioned JSON contracts:

- `scena.photo_plan.v1`
- `scena.photo_candidate_plan.v1`
- `scena.photo_shaded_candidate_selection.v1`
- `scena.photo_render_result.v1`
- `scena.photo_report.v1`
- `scena.exposure_report.v1`
- `scena.focus_report.v1`
- `scena.subject_observation.v1`

`scena photo plan` exposes the deterministic candidate plan without rendering
the final image. `scena photo render` runs a bounded camera/exposure loop,
writes a PNG, and writes `scena.photo_report.v1` to the requested report path.

Recipe render introspection can now include subject observations, exposure
reports, and focus reports when the recipe requests subject-aware metering,
subject focus, or camera-behavior verification.

## Compatibility

All new fields and commands are additive. Existing recipes that omit
`photo.intent` keep the prior explicit-render behavior:

- fixed `render.exposure_ev` remains full manual exposure;
- manual `render.depth_of_field.focus_distance` remains valid;
- explicit `render.metering:{mode:"average"}` with auto exposure remains
  average metering and does not silently become subject metering.

For auto-exposed product/studio renders that need a small brightness nudge, use
`render.exposure_compensation_ev` with `render.auto_exposure`. Use fixed
`render.exposure_ev` only for deliberately manual shots.

## Known limitations

- Strict camera-behavior evidence currently requires CPU/headless subject-mask and
  scene-linear pre-tonemap metering evidence. GPU/browser camera-behavior proof is
  reported as degraded unless the active lane supplies backend-specific subject
  observation and metering proof.
- Transparent subjects cannot always produce exact subject identity. Use
  opaque or masked fallback geometry for strict subject-mask evidence.
- Candidate counts are bounded. `scena.photo_report.v1` reports the evaluated
  candidate budget and selected candidate; it is not an unbounded optimizer.
- The first acceptance fixture uses explicit camera-behavior quality bands. Those
  bands are proof thresholds for the fixture and are not a universal
  photographic taste model.
